## Global constraints

Every task is bound by the constraints below; the values are copied from the spec.

- One app `apps/metis`; no multi-package workspace, no path aliases (spec 3.1). The Expo template
  already has the alias `@/*` in `tsconfig.json`: it must be removed.
- pnpm installs in the `nodeLinker: hoisted` mode (spec 2), written in `apps/metis/pnpm-workspace.yaml`.
- Boundaries (spec 3.2): `src/core/` and every `model.ts` do not import `react`, `react-native`,
  `src/design-system/`, `src/platform/`, `src/shell/`, `src/screens/`, `src/mocks/`, and do not use
  `window`, `document`, `localStorage`; `src/design-system/` does not import `src/core/i18n`,
  `src/platform/`, `src/shell/`, `src/screens/`, `src/mocks/`; a screen does not import another screen;
  only `src/platform/` and tests may import `src/mocks/`.
- `brand/tokens.css` is the only source of the shape numbers and colors; `src/design-system/tokens.ts`
  is generated only by `scripts/gen-tokens.mjs` and never edited by hand (spec 5.1).
- No number and no color code written directly in a style for size, spacing, corner radius, font size, line
  height, color; no style written directly in JSX; there are only two kinds of exception, and each place has
  `// token-exception: <reason>` on the line right above (spec 7).
- All displayed text goes through the typed dictionary; design system components receive text through a
  required prop (spec 5.5).
- A screen never counts or sums rows itself; every number is a snapshot from the server (spec 3.3).
- Coverage 100% of lines, branches, functions, statements; mutation testing with a 100% threshold (a decision of this
  plan, section "Decisions made while writing the plan"); Knip clean, except for the debt list, which may only shrink
  (spec 9.1).
- Each gate is a command `pnpm gate:<name>` that can be run on the machine (spec 9.3).
- Comments in the code are written in Vietnamese; names of functions, variables and files are written in English.
- No long dash character (em dash, en dash) anywhere.
- The implementer does not run `git add`, `git commit`, `git push`, `git init`; the last step of each task
  lists the changed files and stops.
- Every command runs from the app folder `apps/metis`, unless a step says otherwise. The variable `REPO` is the repo root.
- Before running the gates at the end of each task, run `pnpm exec prettier --write .` once: the code
  in the plan may not match Prettier's line breaks exactly.
- After each task, every gate that exists up to that task must be green.

## Places that need a careful check

Five kinds of input that the spec implies but that the main tests easily miss, ordered by how likely they are to cause an error for
the user. The first four items have tests in this plan; the last item belongs to the UI, so its test
is in the second plan.

1. **Invalid saved language choice** (old value, wrong letter case, empty, not a
   string): the app uses English. Test in Task 3 (`resolveLocale`).
2. **Network failure, timeout, the server returns an unknown code or data of the wrong shape:** the client returns a named error
   (network, timeout, not signed in, no permission, not found, server, wrong shape
   with the name of the wrong field), and never throws an unnamed error up to the screen. Tests in Task 6
   (shape) and Task 7 (the call path).
3. **Odd path parameters** (a project code with spaces, slashes, accented letters, `?`, `#`): the client
   encodes the parameter and never calls the wrong path. Test in Task 7.
4. **A snapshot with missing metrics, "not baselined", very large numbers, an odd time zone, midnight:** the contract
   rejects a snapshot with missing metrics and an odd time zone, naming the field, accepts "not baselined" and numbers up to millions;
   midnight shows as `00:00`. Tests in Task 5 and Task 6; how it shows on screen is in the second plan.
5. **Vietnamese text longer than English at phone width:** the second plan.

## Decisions made while writing the plan

Each line: what was decided, why, the price to pay if it is wrong.

- **Two plans in sequence.** This plan has no UI; the second plan holds the design
  system, the page frame, the overview screen and the gates that run in the browser and on the app. Why: the
  UI code must be tried out on a real foundation before delivery, as promised to the product owner.
  Price: one more round of plan review.
- **Mutation testing with a 100% threshold, where the spec proposes 90%.** The trial measured: a 90% threshold lets one
  surviving mutant through out of 11. A mutant that truly does not change behavior is switched off one place at a time with
  `// Stryker disable next-line <mutator>: <reason>`, and a lint rule demands the reason. While writing this
  plan, three surviving mutants were handled by rewriting the code or adding a test, with no
  disable line at all. Price: more effort to write tighter tests; spec section 12 is updated accordingly.
- **pnpm 11.28.4 with `nodeLinker: hoisted`.** The spec says pnpm 10.34.6; the machine has 11.3.0, but pnpm
  11.3.0 in hoisted mode prints `Done in` and then does not exit when installing over an existing `node_modules` (the verbatim trial
  run measured 3 hangs out of 3 attempts, one of 715 seconds; a pnpm bug, fixed in 11.23.0 and
  11.26.0). `packageManager` pins 11.28.4 (the newest version 11, released on 03/10/2026) from Task 1 Step 2,
  so pnpm 11.3.0 on the machine and `pnpm/action-setup` in CI both use that version on their own. create-expo does not write
  `nodeLinker`, so Task 1 writes it. The hoisted mode keeps to the spec because the iOS and Android builds have only been
  proven with this mode; every gate of this plan is green in both modes. Price: the first pnpm run
  downloads pnpm 11.28.4 (about 4 seconds). Spec section 2 is updated with the version number.
- **Web exports in single-page mode (`web.output: "single"`), not the template's `static`.** The web
  trial measured: static mode turns a dynamic route into a file
  `w/[workspaceId]/projects/[projectId]/overview.html`, so opening a deep path directly lands on the wrong home
  page; single-page mode plus a server that returns `index.html` for every path opens the right page. Price: the page
  draws nothing before the JavaScript bundle finishes running (this affects the 2 second target on a phone, to be re-measured
  in the second plan).
- **Every web export uses `--clear`.** The trial measured: dropping this flag after an export that had the mock
  server makes the release build carry the mock server along. Price: each export is a few seconds slower.
- **Keep `react-native-reanimated`, `react-native-worklets`, `react-native-gesture-handler` as the template
  pinned them.** expo-router pulls them in as peers of `react-native-drawer-layout`; removing them from
  `package.json` still makes pnpm install them on its own, but without pinning a version (the trial measured 4.7.1 available,
  while SDK 57 goes with 4.5.1). Knip does not flag them. Price: none.
- **React Native Testing Library is not installed in this plan.** There is no component yet; a package nobody
  uses makes Knip go red. The second plan installs it together with the first component test, and runs it only
  on the iOS and Android projects of Jest (the trial measured that it cannot render on the Web and Node projects).
- **Times are shown in the workspace's time zone, carried in the contract (`timeZone`).** BRD 12.1 computes "today"
  in the workspace time zone; showing times in the same zone keeps the overdue date and "As of" from differing
  by a day, and makes the screen look the same on CI, a Mac and a phone. Price if wrong: remove one
  field and one parameter.
- **The date-time strings and numbers in the tests are the strings that Node 24.15.0 prints.** English uses `en-GB`:
  month 9 is written "Sept" (CLDR data), the wireframe says "Sep"; the plan does not build date strings itself
  to match every letter. The native trial measured: Hermes on Android prints exactly the string Node prints with
  exactly the options of `format.ts` (`22 Sept 2026, 09:40`, `09:40 22 thg 9, 2026`); Hermes on
  iPhone prints Vietnamese in the `dateStyle` form as `09:40 ngay 22 thg 9, 2026`, and with the options of
  `format.ts` it has not been measured. The Maestro flow in the second plan keeps the expected string per platform.
- **The dictionary check is a pure function in `src/core/` with a test**, not a separate script:
  it is inside coverage and mutation testing like any other code. The test that runs on the real dictionary is added
  in the second plan, when the first dictionary exists.
- **The mock data `src/mocks/fixtures/` is inside coverage but outside mutation testing.** It is data,
  not logic: a mutant that changes one letter in the data is killed only by a test that copies the data back
  verbatim. The contract test pins it (parse, then compare in full), and the second plan
  compares it with the wireframe on screen. The handlers of the mock server stay inside mutation testing.
- **The tools in `scripts/` and `eslint-rules/` are bound by 100% coverage and the rule "every file has a test
  next to it", and are not bound by mutation testing.** StrykerJS has no runner for `node --test`; the reverse tests
  (Task 9) are the end-to-end test for each gate. Price: a surviving mutant in the tools can
  slip through, and the reverse tests catch most of them.
- **Reverse tests only create new files or append to generated files.** The case "change a number in
  `brand/tokens.css` without regenerating" of spec section 10 is done by appending one line to
  `tokens.ts`: the same difference check, but never touching the source of truth shared with the
  wireframe. Price: it cannot test the generator reading the CSS wrongly; the generator's own tests take care of that.
- **CI runs exactly `pnpm verify` on every push to `main` and every pull request; the reverse tests
  run on a weekly schedule and on a manual trigger.** Spec 11.1 splits this into three cadences; with this plan the whole set
  runs in 1 to 2 minutes (measured 62 to 101 seconds), so there is no need to split yet. The `--publish-status` flag is not built:
  metis has no GitHub repo and no account of its own yet (spec section 13). CI can only run when the repo has a
  remote.
- **The computed health in the contract carries only the overall level and the reasons of two dimensions, delivery and risk.**
  Spec 3.5 gives a level and reasons per dimension (delivery, risk, resources, finance), but the BRD
  has no rule yet for project health in the resources and finance dimensions, and screen 24 does not show a separate level
  per dimension; every value there would be invented data. The list of reason kinds is closed: when the back-end adds a
  new kind, the contract changes on both sides. Recorded in the open questions of the spec. Price if wrong: one more contract
  change, which does not break what already exists.
- **The Delayed tile drills down with `delayed=true`.** BRD WBS-05 has no "late against
  baseline" filter; the mock data uses this name, and the back-end decides. Recorded in the open questions of the spec.
- **The dependency gate accepts four vulnerabilities that exist in the package tree of Expo SDK 57; the product owner
  must approve.** `pnpm audit --prod` measured four advisories (two high, two moderate): three are in the build tools
  (`node-forge`, `braces`, `uuid`) and do not enter the app bundle; one (`decode-uri-component` through
  expo-router) is in the app bundle but only slows the tab of a person who opens a broken path by hand.
  Forcing the patched version with `overrides` could break Expo, not measured. The list is in
  `pnpm-workspace.yaml`, one reason per advisory, and may only shrink; every new vulnerability turns the gate red. Price
  if wrong: if the product owner wants to block all four, they must wait for Expo to fix it or try `overrides`.
- **Allowed licenses: the permissive licenses plus MPL-2.0**, and no GPL, AGPL or LGPL standing
  alone. The gate only judges packages that go into the app (`--prod`), not development tools. Needs the product owner's approval.
- **The dependency gate runs on every `pnpm verify`, not only on a schedule as in spec 11.1.** It is fast
  (2 to 4 seconds on pnpm 11.28.4) and goes red as soon as a new vulnerability appears. Price: a new vulnerability can turn
  red a pull request that touches no package, until it is reviewed; the gate needs the network.

```js
// Token gate (spec 7): values in StyleSheet.create come from tokens.ts, with no number or color
// code written directly. It applies to size, spacing, corner radius, font size, line height, color. It does not apply to
// unitless properties (flex, opacity, zIndex), the number 0, and a border of 1 (style guide section 5). A value written
// directly is allowed when the line right above says `// token-exception: <reason>`.
const SIZED =
  /^(width|height|(min|max)(Width|Height)|margin\w*|padding\w*|gap|rowGap|columnGap|top|right|bottom|left|start|end|inset\w*|border\w*Radius|fontSize|lineHeight|letterSpacing)$/
const BORDER_WIDTH = /^border\w*Width$/
const COLOUR_KEY = /color$/i
const COLOUR_CODE = /#[0-9a-f]{3,8}\b|\b(rgba?|hsla?)\(/i
// TypeScript type wrappers (as, satisfies, !, <T>) do not change the value: unwrap them and check the value inside.
const TS_WRAPPERS = new Set([
  'TSAsExpression',
  'TSSatisfiesExpression',
  'TSNonNullExpression',
  'TSTypeAssertion'
])

// The nodes that can be the final value of an expression: unwrap type wrappers, take both branches of ?:
// and both sides of ??, ||, &&. Strings joined with + are not visited.
const valuesIn = (node) => {
  if (TS_WRAPPERS.has(node.type)) return valuesIn(node.expression)
  if (node.type === 'ConditionalExpression') {
    return [...valuesIn(node.consequent), ...valuesIn(node.alternate)]
  }
  if (node.type === 'LogicalExpression') return [...valuesIn(node.left), ...valuesIn(node.right)]
  return [node]
}

// Numbers in an expression: the values above, plus numbers inside a minus sign and arithmetic (+, -, *, /).
const numbersIn = (node) =>
  valuesIn(node).flatMap((value) => {
    if (value.type === 'Literal') return typeof value.value === 'number' ? [value] : []
    if (value.type === 'UnaryExpression') return numbersIn(value.argument)
    if (value.type === 'BinaryExpression') {
      return [...numbersIn(value.left), ...numbersIn(value.right)]
    }
    return []
  })

const isColourLiteral = (key, node) =>
  node.type === 'Literal' &&
  typeof node.value === 'string' &&
  ((COLOUR_KEY.test(key) && node.value !== 'transparent') || COLOUR_CODE.test(node.value))

module.exports = {
  meta: {
    type: 'problem',
    docs: { description: 'Style values in StyleSheet.create come from tokens.ts' },
    messages: {
      number: '{{key}}: use a token from tokens.ts instead of the number {{value}}',
      colour: '{{key}}: use a color token from tokens.ts instead of {{value}}'
    },
    schema: []
  },
  create(context) {
    const excepted = (property) =>
      context.sourceCode
        .getCommentsBefore(property)
        .some(
          (c) =>
            c.type === 'Line' &&
            /^\s*token-exception:\s*\S/.test(c.value) &&
            c.loc.end.line === property.loc.start.line - 1
        )

    const numbersToReport = (key, value) => {
      const found = numbersIn(value).filter((n) => n.value !== 0)
      if (SIZED.test(key)) return found
      if (BORDER_WIDTH.test(key)) return found.filter((n) => n.value !== 1)
      return []
    }

    const check = (property) => {
      const key =
        property.key.type === 'Identifier' ? property.key.name : String(property.key.value)
      if (excepted(property)) return
      for (const node of numbersToReport(key, property.value)) {
        context.report({ node, messageId: 'number', data: { key, value: node.raw } })
      }
      for (const node of valuesIn(property.value)) {
        if (isColourLiteral(key, node)) {
          context.report({ node, messageId: 'colour', data: { key, value: node.raw } })
        }
      }
    }

    return {
      "CallExpression[callee.object.name='StyleSheet'][callee.property.name='create'] > ObjectExpression > Property > ObjectExpression Property":
        check
    }
  }
}
```

```js
// Generates src/design-system/tokens.ts from brand/tokens.css (spec 5.1).
// Usage: node scripts/gen-tokens.mjs           writes the file
//       node scripts/gen-tokens.mjs --check   exits 1 when the file is missing or stale compared with brand/tokens.css
import { existsSync, readFileSync, realpathSync, writeFileSync } from 'node:fs'
import { resolve } from 'node:path'
import { fileURLToPath } from 'node:url'

const camel = (name) => name.replace(/-([a-z0-9])/g, (_, c) => c.toUpperCase())
const quote = (text) => `'${text.replace(/\\/g, '\\\\').replace(/'/g, "\\'")}'`

// Reads the :root block; a "Npx" value becomes a number, other values stay as strings (color, font, shadow).
export function parse(css) {
  const body = css.replace(/\/\*[\s\S]*?\*\//g, '').match(/:root\s*\{([\s\S]*?)\}/)
  if (!body) throw new Error('brand/tokens.css has no :root block')
  const tokens = new Map()
  for (const declaration of body[1].split(';')) {
    const text = declaration.trim()
    const match = text.match(/^--([a-z0-9-]+)\s*:\s*([\s\S]+)$/i)
    if (!match) {
      // A CSS variable that cannot be read and is skipped silently loses a token while the --check gate stays green: stop.
      if (text.startsWith('--')) throw new Error(`cannot read declaration "${text}"`)
      continue
    }
    const [, name, raw] = match
    const key = camel(name)
    if (tokens.has(key)) throw new Error(`duplicate token --${name}`)
    const value = raw.trim().replace(/\s+/g, ' ')
    const px = value.match(/^(-?\d+(?:\.\d+)?)px$/)
    tokens.set(key, px ? Number(px[1]) : value)
  }
  return tokens
}

export function render(tokens) {
  const lines = [...tokens].map(
    ([key, value]) => `  ${key}: ${typeof value === 'number' ? value : quote(value)}`
  )
  return [
    '// GENERATED by scripts/gen-tokens.mjs from brand/tokens.css. Do not edit by hand.',
    `// ${tokens.size} tokens. Regenerate: pnpm gen:tokens`,
    'export const tokens = {',
    lines.join(',\n'),
    '} as const',
    ''
  ].join('\n')
}

// Returns the exit code: 0 when written, or when --check finds the file matching; 1 when --check finds the file missing or stale.
export function run({ source, out, check, log }) {
  const tokens = parse(readFileSync(source, 'utf8'))
  const next = render(tokens)
  if (!check) {
    writeFileSync(out, next)
    log(`gen-tokens: wrote ${tokens.size} tokens to ${out}`)
    return 0
  }
  if (existsSync(out) && readFileSync(out, 'utf8') === next) {
    log(`gen-tokens --check: up to date (${tokens.size} tokens)`)
    return 0
  }
  log(`gen-tokens --check: ${out} is stale; run pnpm gen:tokens`)
  return 1
}

/* node:coverage disable */
// Runs only when called from the command line; gate:tokens and the token-stale reverse test run this part.
if (process.argv[1] && realpathSync(process.argv[1]) === fileURLToPath(import.meta.url)) {
  const appRoot = resolve(import.meta.dirname, '..')
  process.exitCode = run({
    source: resolve(appRoot, '../../brand/tokens.css'),
    out: resolve(appRoot, 'src/design-system/tokens.ts'),
    check: process.argv.includes('--check'),
    log: console.log
  })
}
```

```ts
// Typed dictionary (spec 5.5). The en.ts of each screen is the source, written `as const`; vi.ts declares
// `const vi: Dictionary<typeof en>`, so a missing key, a redundant key or a mismatched level is a compile error.
export type Dictionary<T> = {
  readonly [K in keyof T]: T[K] extends string ? string : Dictionary<T[K]>
}

const SLOT = /\{\w+\}/g

// The names of the {name} placeholders in a sentence, with no repeats, in alphabetical order.
export const placeholders = (template: string): string[] =>
  [...new Set((template.match(SLOT) ?? []).map((slot) => slot.slice(1, -1)))].sort()

// Fills the placeholders. Numbers must go through src/core/format.ts first, so values accept only strings. A missing value
// is a programmer error: throw an error instead of letting "{name}" show on the screen.
export function interpolate(template: string, values: Readonly<Record<string, string>>): string {
  return template.replace(SLOT, (slot) => {
    const value = values[slot.slice(1, -1)]
    // typeof, not a comparison with undefined: {constructor} or {toString} must not take a value inherited
    // from Object.prototype.
    if (typeof value !== 'string') throw new Error(`missing value for ${slot} in "${template}"`)
    return value
  })
}
```

```ts
import { placeholders } from './dictionary'

// Nested groups of sentences, like the en.ts and vi.ts of a screen.
type Tree = { readonly [key: string]: string | Tree }

export type AuditIssue = {
  key: string
  problem: 'missing' | 'placeholders' | 'untranslated' | 'stale'
}

const flatten = (tree: Tree, prefix = ''): [string, string][] =>
  Object.entries(tree).flatMap(([key, value]): [string, string][] =>
    typeof value === 'string' ? [[prefix + key, value]] : flatten(value, `${prefix}${key}.`)
  )

// Checks the translation against the source (spec 5.5): all keys present, the same set of {name} placeholders, and does not leave
// the source sentence unchanged, except for keys in sameAllowed (proper names, symbols like "PM"). A key in sameAllowed
// must exist in the source and be translated identically, otherwise the list is out of date (stale), reported after the other errors.
export function auditDictionaries(
  source: Tree,
  translation: Tree,
  sameAllowed: readonly string[]
): AuditIssue[] {
  const entries = flatten(source)
  const original = new Map(entries)
  const translated = new Map(flatten(translation))
  const issues = entries.flatMap(([key, text]): AuditIssue[] => {
    const other = translated.get(key)
    if (other === undefined) return [{ key, problem: 'missing' }]
    if (placeholders(text).join() !== placeholders(other).join()) {
      return [{ key, problem: 'placeholders' }]
    }
    if (text === other && !sameAllowed.includes(key)) return [{ key, problem: 'untranslated' }]
    return []
  })
  const stale = sameAllowed
    .filter((key) => !original.has(key) || translated.get(key) !== original.get(key))
    .map((key): AuditIssue => ({ key, problem: 'stale' }))
  return [...issues, ...stale]
}
```

```ts
import type { Locale } from './i18n/locale'

// Language tags for Intl (spec 5.5): en-GB for dates in the "25 Jun 2026" style, like the wireframe.
const INTL_TAG: Record<Locale, string> = { en: 'en-GB', vi: 'vi-VN' }

const DATE = { day: 'numeric', month: 'short', year: 'numeric' } as const
// h23: midnight is 00:00, never 24:00 or 12:00 AM.
const TIME = { hour: '2-digit', minute: '2-digit', hourCycle: 'h23' } as const

export const formatInteger = (locale: Locale, value: number) =>
  new Intl.NumberFormat(INTL_TAG[locale]).format(value)

// value is in percent: 25 is 25%. Rounds down to an integer (FE-20): 99,5% shows 99%, and a project
// that still has work never shows 100%. Round with Math.floor before passing to Intl, not relying
// on the roundingMode option of Intl (not measured on Hermes).
export const formatPercent = (locale: Locale, value: number) =>
  new Intl.NumberFormat(INTL_TAG[locale], { style: 'percent' }).format(Math.floor(value) / 100)

// Calendar date "YYYY-MM-DD" (for example the baseline date): it has no time, so it does not change with the time zone.
export const formatDate = (locale: Locale, day: string) =>
  new Intl.DateTimeFormat(INTL_TAG[locale], { ...DATE, timeZone: 'UTC' }).format(new Date(day))

// An ISO instant, shown in the time zone of the workspace (the timeZone field of the contract).
export const formatDateTime = (locale: Locale, instant: string, timeZone: string) =>
  new Intl.DateTimeFormat(INTL_TAG[locale], { ...DATE, ...TIME, timeZone }).format(
    new Date(instant)
  )

export const formatTime = (locale: Locale, instant: string, timeZone: string) =>
  new Intl.DateTimeFormat(INTL_TAG[locale], { ...TIME, timeZone }).format(new Date(instant))
```

Why every value of every code list has a test written out literally, not a loop over the list
of the contract itself: mutation testing changes one code into an empty string; a test that loops over the list
that was changed stays green.

Why there are rejection rows and three generated tables: StrykerJS does not generate mutants for the constraint chains of
zod (`.int()`, `.nonnegative()`, `.positive()`, `.min(1)`), so a constraint that is loosened still leaves the
mutation score at 100%. Each constraint therefore has a row that pins it down: hand-written rows for each kind of error, three
generated tables for every count field, required text field and positive integer field. Each row may
break only one spot, and the error must be exactly at that field. The three ways of dropping `.nonnegative()` on the totals of the three
lists do not change whether a value is accepted or rejected, because the row-count check still blocks a negative number.

```ts
import { z } from 'zod'

// The contract of the project overview screen (spec 3.5): what is handed over to the back-end (FE-10).
// Every number is a snapshot the server computes per BRD section 12; the screen never counts or sums rows itself (spec 3.3).
// The data carries only codes and user content; the display label of a code lives in the screen's dictionary.

const count = z.number().int().nonnegative()
const text = z.string().min(1)
// An instant in UTC with the Z suffix; the screen converts to the workspace time zone when displaying.
const instant = z.iso.datetime()
const day = z.iso.date()
const freshness = z.enum(['fresh', 'stale', 'partial', 'unknown'])
const label = z.enum(['milestone', 'checkpoint', 'approvalGate', 'inputRequired', 'riskRelated'])

// Intl throws on an unrecognized time zone; check at the entry so the screen does not break when formatting times.
function isTimeZone(zone: string): boolean {
  try {
    Intl.DateTimeFormat('en', { timeZone: zone })
  } catch {
    return false
  }
  return true
}

// The drill-down filter is built by the server (BR-32), parameter names follow the WBS fields (spec 4.3). The screen only copies
// the filter into the path, never builds it.
const drill = z.record(text, z.array(text).min(1))

// The part common to every metric snapshot (BR-39).
const snapshot = {
  asOf: instant,
  definitionVersion: z.number().int().positive(),
  freshness,
  drill
}

const tile = z.object({ ...snapshot, value: count })
const item = { id: text, code: text, name: text, labels: z.array(label) }

export const overviewSchema = z.object({
  // IANA time zone of the workspace: the BRD 12.1 "today" and every time on the screen follow this zone.
  timeZone: z.string().refine(isTimeZone),
  project: z.object({
    name: text,
    client: text,
    pm: text,
    stage: z.object({
      name: text,
      index: z.number().int().positive(),
      count: z.number().int().positive()
    }),
    declaredHealth: z.enum(['green', 'amber', 'red']),
    framework: z.object({ name: text, version: text }),
    baseline: z.object({ version: z.number().int().positive(), date: day }).nullable(),
    savedAt: instant
  }),
  metrics: z.object({
    workItems: z.object({ ...snapshot, value: count, categoryRowsExcluded: count }),
    deliverables: tile,
    workPackages: tile,
    milestones: z.object({ ...snapshot, value: count, overdue: count }),
    approvalGates: z.object({ ...snapshot, value: count, overdue: count }),
    blocked: tile,
    // "not baselined" when the project has no baseline yet (BRD 12.1, Delayed row).
    delayed: z.discriminatedUnion('state', [
      z.object({
        ...snapshot,
        state: z.literal('measured'),
        value: count,
        sinceBaseline: z.number().int(),
        baselineVersion: z.number().int().positive()
      }),
      z.object({ ...snapshot, state: z.literal('notBaselined') })
    ]),
    highRisk: z.object({ ...snapshot, value: count, critical: count }),
    progress: z.object({
      ...snapshot,
      value: z.number().min(0).max(100),
      done: count,
      total: count
    })
  }),
  statusBreakdown: z.array(
    z.object({
      status: z.enum(['done', 'inProgress', 'waiting', 'blocked', 'notStarted']),
      count,
      drill
    })
  ),
  progressByCategory: z.array(z.object({ name: text, done: count, total: count, drill })),
  workload: z.array(z.object({ name: text, open: count, drill })),
  // Each list carries a total and a few first rows chosen by the server; the number of rows shown never exceeds the total, so
  // the screen's "N more" part never gives a negative number.
  attention: z.object({
    upcoming: z
      .object({ total: count, items: z.array(z.object({ ...item, targetDate: day })) })
      .refine((l) => l.items.length <= l.total, { path: ['total'] }),
    overdue: z
      .object({
        total: count,
        items: z.array(z.object({ ...item, daysOverdue: z.number().int().positive() }))
      })
      .refine((l) => l.items.length <= l.total, { path: ['total'] }),
    risks: z
      .object({
        total: count,
        items: z.array(z.object({ ...item, riskLevel: z.enum(['high', 'critical']) }))
      })
      .refine((l) => l.items.length <= l.total, { path: ['total'] })
  }),
  computedHealth: z.object({
    level: z.enum(['green', 'amber', 'red', 'unknown']),
    reasons: z.array(
      z.discriminatedUnion('kind', [
        z.object({ kind: z.literal('overdueItems'), count, milestones: count }),
        z.object({ kind: z.literal('criticalRisksWithoutMitigation'), count })
      ])
    )
  })
})
```

```ts
import type { z } from 'zod'

import { type Overview, overviewSchema } from './overview'

// Named errors that the screen knows how to draw (spec 3.3, 4.5). The client never throws an error to the screen.
type ApiError =
  | { kind: 'unauthenticated' }
  | { kind: 'forbidden' }
  | { kind: 'notFound' }
  | { kind: 'server'; status: number }
  | { kind: 'invalid'; issues: { path: string; message: string }[] }
  | { kind: 'network' }
  | { kind: 'timeout' }

export type ApiResult<T> = { ok: true; data: T } | { ok: false; error: ApiError }

export type ApiConfig = { baseUrl: string; timeoutMs: number }

const STATUS_ERRORS: Partial<Record<number, ApiError>> = {
  401: { kind: 'unauthenticated' },
  403: { kind: 'forbidden' },
  404: { kind: 'notFound' }
}

const fail = (error: ApiError): { ok: false; error: ApiError } => ({ ok: false, error })

function parse<T>(schema: z.ZodType<T>, text: string): ApiResult<T> {
  let body: unknown
  try {
    body = JSON.parse(text)
  } catch {
    return fail({ kind: 'invalid', issues: [{ path: '', message: 'body is not JSON' }] })
  }
  const result = schema.safeParse(body)
  if (result.success) return { ok: true, data: result.data }
  const issues = result.error.issues.map((issue) => ({
    path: issue.path.join('.'),
    message: issue.message
  }))
  return fail({ kind: 'invalid', issues })
}

// Never throws: every failure becomes an ApiError.
async function request<T>(
  url: string,
  schema: z.ZodType<T>,
  signal: AbortSignal
): Promise<ApiResult<T>> {
  try {
    const response = await fetch(url, { signal })
    if (!response.ok) {
      return fail(STATUS_ERRORS[response.status] ?? { kind: 'server', status: response.status })
    }
    return parse(schema, await response.text())
  } catch {
    return fail(signal.aborted ? { kind: 'timeout' } : { kind: 'network' })
  }
}

// The timer is dropped only after the response body has been read, so the timeout covers the body read too: fetch
// cancels the read when the signal is aborted.
async function getJson<T>(url: string, schema: z.ZodType<T>, timeoutMs: number) {
  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), timeoutMs)
  const result = await request(url, schema, controller.signal)
  clearTimeout(timer)
  return result
}

// An empty id, "." or ".." stays unchanged through encodeURIComponent, and then the URL merges them into the path
// (".." goes up one level) and the call lands on another page. Such an id does not exist: return notFound, do not
// call the network.
const isRouteId = (id: string) => id !== '' && id !== '.' && id !== '..'

// GET {baseUrl}/workspaces/{workspaceId}/projects/{projectId}/overview (spec 3.5). The ids are taken from the path
// supplied by the user so they are encoded: spaces, slashes and accented letters do not corrupt the call path.
export const getOverview = (
  config: ApiConfig,
  workspaceId: string,
  projectId: string
): Promise<ApiResult<Overview>> => {
  if (!isRouteId(workspaceId) || !isRouteId(projectId)) {
    return Promise.resolve(fail({ kind: 'notFound' }))
  }
  return getJson(
    `${config.baseUrl}/workspaces/${encodeURIComponent(workspaceId)}/projects/${encodeURIComponent(projectId)}/overview`,
    overviewSchema,
    config.timeoutMs
  )
}
```

The response body is read with `text()` and then `JSON.parse` in the app's own code: the `SyntaxError` thrown from
`response.json()` belongs to Node's realm, so comparing with `instanceof` in Jest would fail.

```js
// The pnpm verify command (spec 11.2): runs every gate:* script in the order declared in package.json,
// prints and writes reports/verify.md (one row per gate, with the commit id), exits 1 when a gate is red.
// CI calls exactly this command, no checking logic lives only in the CI file (spec 9.3).
import { execFileSync, spawnSync } from 'node:child_process'
import { mkdirSync, readFileSync, realpathSync, writeFileSync } from 'node:fs'
import { fileURLToPath } from 'node:url'

export const gatesOf = (scripts) => Object.keys(scripts).filter((name) => name.startsWith('gate:'))

export function commitOf(git) {
  try {
    return git()
  } catch {
    return 'no commit yet'
  }
}

// Run every gate, even after a red gate, so one run shows all the errors.
export function verify({ gates, run, now }) {
  if (gates.length === 0) throw new Error('package.json has no gate:* scripts')
  const results = gates.map((gate) => {
    const start = now()
    const ok = run(gate)
    return { gate, ok, seconds: (now() - start) / 1000 }
  })
  return { results, code: results.every((result) => result.ok) ? 0 : 1 }
}

export function report(commit, results) {
  const rows = results.map(
    ({ gate, ok, seconds }) => `| ${gate} | ${ok ? 'green' : 'RED'} | ${seconds.toFixed(1)} |`
  )
  return [
    '# pnpm verify',
    '',
    `Commit: ${commit}`,
    '',
    '| Gate | Result | Seconds |',
    '|---|---|---|'
  ]
    .concat(rows, '')
    .join('\n')
}

/* node:coverage disable */
// Runs only when called from the command line: pnpm verify, and CI.
if (process.argv[1] && realpathSync(process.argv[1]) === fileURLToPath(import.meta.url)) {
  const { scripts } = JSON.parse(readFileSync('package.json', 'utf8'))
  const { results, code } = verify({
    gates: gatesOf(scripts),
    run: (gate) => spawnSync('pnpm', ['run', gate], { stdio: 'inherit' }).status === 0,
    now: () => performance.now()
  })
  const git = () =>
    execFileSync('git', ['rev-parse', 'HEAD'], { stdio: ['ignore', 'pipe', 'ignore'] })
      .toString()
      .trim()
  const text = report(commitOf(git), results)
  mkdirSync('reports', { recursive: true })
  writeFileSync('reports/verify.md', text)
  console.log(`\n${text}`)
  process.exitCode = code
}
/* node:coverage enable */
```

```js
// The reverse test (spec 10): demand the gate green first, plant a deliberate defect, run the same gate again and it must catch
// that defect, demand the gate red because of exactly that defect, then restore everything whatever the result. A gate that stays green with a defect
// planted is a blind gate.
// Usage: pnpm canary <name>, or pnpm canary all
import { spawnSync } from 'node:child_process'
import { existsSync, readFileSync, realpathSync, rmSync, writeFileSync } from 'node:fs'
import { join } from 'node:path'
import { fileURLToPath } from 'node:url'

// Each test: the gate that must go red, the string that must be in the gate's message, the files to create (create) and the strings appended
// to the end of an existing file (append). Only append to generated files, never edit a hand-written source file.
// These six tests are the part of spec section 10 that can be done before there is a UI; the second plan adds the rest.
export const CANARIES = {
  'token-literal': {
    gate: 'lint',
    expect: 'local/no-style-literals',
    create: {
      'src/design-system/canary-style.ts':
        "import { StyleSheet } from 'react-native'\n\nexport const styles = StyleSheet.create({ box: { padding: 8 } })\n"
    }
  },
  'token-stale': {
    gate: 'tokens',
    expect: 'is stale',
    append: { 'src/design-system/tokens.ts': '// canary\n' }
  },
  compat: {
    gate: 'lint',
    expect: 'compat/compat',
    create: {
      'src/design-system/canary-compat.ts':
        'export const idle = () => window.requestIdleCallback(() => undefined)\n'
    }
  },
  deadcode: {
    gate: 'deadcode',
    expect: 'canary-dead.ts',
    create: {
      'src/core/canary-dead.ts': 'export const used = 1\nexport const unused = 2\n',
      'src/core/canary-dead.test.ts':
        "import { used } from './canary-dead'\n\ntest('used', () => expect(used).toBe(1))\n"
    }
  },
  coverage: {
    gate: 'unit',
    expect: 'coverage threshold',
    create: { 'src/core/canary-untested.ts': 'export const untested = (n: number) => n + 1\n' }
  },
  mutation: {
    gate: 'mutation',
    expect: 'breaking threshold',
    create: {
      'src/core/canary-weak.ts': 'export const double = (n: number) => n * 2\n',
      'src/core/canary-weak.test.ts':
        "import { double } from './canary-weak'\n\n// Runs through the code without asserting anything: coverage is enough, the mutant survives.\ntest('runs', () => {\n  double(2)\n})\n"
    }
  }
}

// Plant the defect, return the function that restores everything.
export function plant(root, canary) {
  const create = Object.entries(canary.create ?? {})
  const append = Object.entries(canary.append ?? {})
  const originals = append.map(([file]) => [file, readFileSync(join(root, file), 'utf8')])
  for (const [file, text] of create) writeFileSync(join(root, file), text)
  for (const [file, text] of originals) writeFileSync(join(root, file), text + canary.append[file])
  return () => {
    // force: a planted file that was deleted midway is skipped, so the remaining files are still restored.
    for (const [file] of create) rmSync(join(root, file), { force: true })
    for (const [file, text] of originals) writeFileSync(join(root, file), text)
  }
}

export function runCanary(name, { root, runGate, log }) {
  if (!Object.hasOwn(CANARIES, name)) throw new Error(`unknown canary "${name}"`)
  const canary = CANARIES[name]
  // A file to be created that already exists (left over from the last run) stops everything before running a gate or touching anything.
  const clash = Object.keys(canary.create ?? {}).find((file) => existsSync(join(root, file)))
  if (clash) throw new Error(`${clash} already exists: remove leftover canary files first`)
  // Green baseline: if the gate is already red before the defect is planted, a later red proves nothing about the planted defect.
  const before = runGate(canary.gate)
  if (before.status !== 0) {
    log(`canary ${name}: gate:${canary.gate} was already red before the defect was planted (code ${before.status})`)
    return false
  }
  const restore = plant(root, canary)
  let outcome
  try {
    outcome = runGate(canary.gate)
  } finally {
    restore()
  }
  const caught = outcome.status !== 0 && outcome.output.includes(canary.expect)
  log(
    caught
      ? `canary ${name}: gate:${canary.gate} red exactly because of the planted defect`
      : `canary ${name}: gate:${canary.gate} did NOT catch the planted defect (code ${outcome.status})`
  )
  return caught
}

/* node:coverage disable */
// Runs only when called from the command line: pnpm canary.
if (process.argv[1] && realpathSync(process.argv[1]) === fileURLToPath(import.meta.url)) {
  // Ctrl+C, closing the terminal (SIGINT, SIGTERM, SIGHUP): wait for the child gate to stop so that
  // finally has time to restore everything.
  for (const signal of ['SIGINT', 'SIGTERM', 'SIGHUP']) process.on(signal, () => {})
  const names = process.argv[2] === 'all' ? Object.keys(CANARIES) : [process.argv[2]]
  const runGate = (gate) => {
    console.log(`running gate:${gate} ...`)
    const result = spawnSync('pnpm', ['run', `gate:${gate}`], { encoding: 'utf8' })
    if (result.signal) throw new Error(`gate:${gate} stopped by ${result.signal}`)
    return { status: result.status, output: result.stdout + result.stderr }
  }
  const caught = names.map((name) =>
    runCanary(name, { root: process.cwd(), runGate, log: console.log })
  )
  process.exitCode = caught.every(Boolean) ? 0 : 1
}
/* node:coverage enable */
```

```js
// Licence gate (spec 9.2): every package in the app (dependencies and the packages they pull in) has a licence
// on the allowed list. SPDX expression: "A OR B" needs one side allowed, "A AND B" needs every side.
import { execFileSync } from 'node:child_process'
import { realpathSync } from 'node:fs'
import { fileURLToPath } from 'node:url'

// Permissive licences, plus MPL-2.0: it only binds the files of the package itself when that package is modified, and the app does not modify it.
const ALLOWED = [
  '0BSD',
  'Apache-2.0',
  'BlueOak-1.0.0',
  'BSD-2-Clause',
  'BSD-3-Clause',
  'CC-BY-4.0',
  'CC0-1.0',
  'ISC',
  'MIT',
  'MPL-2.0',
  'Python-2.0',
  'Unlicense'
]

// SPDX syntax: AND binds tighter than OR, parentheses change the order; an expression with any part that cannot be read is not allowed as a whole.
export const allowed = (expression) => {
  const tokens = [...expression.matchAll(/\(|\)|[^\s()]+/g)].map((match) => match[0])
  let at = 0
  let bad = false
  const orExpr = () => {
    let ok = andExpr()
    while (tokens[at] === 'OR') {
      at++
      ok = andExpr() || ok
    }
    return ok
  }
  const andExpr = () => {
    let ok = atom()
    while (tokens[at] === 'AND') {
      at++
      ok = atom() && ok
    }
    return ok
  }
  const atom = () => {
    const token = tokens[at++]
    if (token !== '(') {
      if (token === undefined || token === ')' || token === 'AND' || token === 'OR') bad = true
      return ALLOWED.includes(token)
    }
    const ok = orExpr()
    if (tokens[at++] !== ')') bad = true
    return ok
  }
  const ok = orExpr()
  return ok && !bad && at === tokens.length
}

// listing: the result of `pnpm licenses list --prod --json`, the key is the licence expression.
export const offenders = (listing) =>
  Object.entries(listing)
    .filter(([expression]) => !allowed(expression))
    .flatMap(([expression, packages]) => packages.map((p) => `${p.name} (${expression})`))

/* node:coverage disable */
// Runs only when called from the command line: gate:deps.
if (process.argv[1] && realpathSync(process.argv[1]) === fileURLToPath(import.meta.url)) {
  const json = execFileSync('pnpm', ['licenses', 'list', '--prod', '--json'], { encoding: 'utf8' })
  const bad = offenders(JSON.parse(json))
  console.log(
    bad.length
      ? `check-licenses: ${bad.length} package(s) outside the allowlist:\n  ${bad.join('\n  ')}`
      : 'check-licenses: every shipped package has an allowed licence'
  )
  process.exitCode = bad.length ? 1 : 0
}
/* node:coverage enable */
```

Why `allowed` reads the expression by SPDX syntax instead of stripping the parentheses and splitting the string: SPDX 2.3.1 annex
D.4.5 makes AND bind tighter than OR, and parentheses change the order. The version that strips parentheses reads `(MIT OR GPL-3.0) AND

AND, OR trees written with parentheses were wrongly let through. Any part that cannot be read (a missing parenthesis, an extra operator, `WITH`)
makes the whole expression not allowed, even when another OR side is valid: the licence gate must block when
unsure. Measured: 0 wrong on 418.744 valid expressions and 2.015.539 arbitrary token strings; fifteen
expressions of the package tree today are still allowed.
